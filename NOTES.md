# Image to Text change log

Newest first. One entry per commit: date, version/build, what changed and why, and how it was checked.

- 2026-10-24: 1.0.0 build 2, two bugs from Brian's handwriting test on build 1 (same PR, not merged).
  - Line order and paragraphs on handwriting. A six-line dash list came out as one paragraph starting with the last line. The cause: orderLines trusted Vision's result order (it only fixed neighbours on the same row), and Vision returns handwriting bottom to top. The y axis itself was already right: the Swift module has flipped every box to top-left (y = 1 - y - height) since build 1, for line boxes, word boxes, second-pass words and page corners, which the tap-a-word source crop uses; this is now documented in the module and mirrored by flipVisionBox for the checks. Fixes in modules/vision-ocr/src/paragraphs.ts: (1) orderLines always sorts, top to bottom then left to right, with pieces of one row (including the two halves of a line written on a slant) joined into one line, and two real columns of text read one after the other (a table such as a receipt stays in rows); (2) LIST_MARKER covers dashes with or without a space, en and em dashes, bullets, checkboxes ("[ ]", "[x]", "\u2610") and "1." "2)" "a)", and a list line is always its own paragraph and never joined to the line before, raw or Clean up (src/text.ts shares the same pattern; a check keeps the two copies identical); (3) two lines are one paragraph only when the gap between them is under 0.6 median line heights of that page (PARAGRAPH_GAP), instead of 0.85.
  - Camera focus. The handwriting photo was soft because build 1 set expo-camera's autofocus to "on", which in expo-camera means focus once and lock; it is now "off", which is continuous autofocus. Tap anywhere on the preview to focus and expose there (a new focusAt in the Swift module sets the point on the back wide-angle camera, the same device expo-camera uses, holds it 3 seconds, FOCUS_HOLD_SECONDS, then goes back to continuous), with a paper ring at the tap that fades. Before a capture is accepted, a sharpness check (variance of the Laplacian on a 512 px grayscale copy of the page area, Core Image, no Vision) runs; under BLUR_THRESHOLD (100, a first guess; each capture logs its value for tuning) the slip "That looks blurry. Hold still and tap the page to focus." offers Retake and Use anyway. Every page read (camera, photos or files) gets the same sharpness number stored (pages.sharpness, added in the same unreleased version 2 migration step), and the hard-to-read note says "Some words were hard to read, and the photo looks out of focus. Hold still and tap the page to focus." when the page was soft.
  - docs/design/after: camera re-rendered, new 22-camera-blurry; 21-result-hard-to-read now shows the focus wording (its fixture page is soft). The focus ring is not in a render: the web renderer does not report tap positions the way iOS does.
  - Checked: npx tsc --noEmit clean; npm test 41 pass (7 new: the dash list in Vision's bottom-origin boxes and bottom-to-top order comes out as six lines and six paragraphs in reading order, raw and cleaned; list markers and what must not count; the 0.6 gap; the slanted line as one line; columns versus a receipt; the tap-to-camera point; the blur threshold), and the dash list fixture was run against the previous orderLines to confirm it reproduces the reversal; npx expo export --platform ios bundles (918 modules); npx expo config --type introspect shows 1.0.0 build 2, ios.entitlements {}, both usage strings, no microphone string. Not checked here: the new Swift compiling (focusAt and sharpness included), how the focus point lines up with the tap on a real preview, and the blur threshold on real photos.
- 2026-10-24: 1.0.0 build 2 (ios.buildNumber 1 to 2; branch claude/trusting-ride-32v6kh restarted from main after PR #1 merged; new PR, not merged).   - Build 1 for the record: PR #1 merged on Brian's go (merge commit 68dfe1a). EAS workflow "Build and submit iOS": the build job succeeded at 03:05 UTC on Oct 22 (about 26 minutes; the first build compiled the Swift module), submit succeeded at 03:16 UTC. GitHub Pages could not be switched on from here (the session's proxy blocks the Pages API); Brian to switch it on in Settings, Pages.
  - Page detection and flattening (modules/vision-ocr): documentBounds(uri) runs VNDetectDocumentSegmentationRequest, falling back to VNDetectRectanglesRequest, and returns the four corners in image pixels and a confidence. flatten(uri, corners) applies CIPerspectiveCorrection to the full-resolution image. In the crop step a found page (confidence 0.6 or more, covering 15% to 97% of the photo, a proper four-sided shape) is preselected as its own outline with a handle on each corner; the corners can be dragged (a drag that would twist the outline stops), rotate keeps the outline, and "Use the whole photo" goes back to the rectangle. With an outline the page is cut out and squared up before recognize(); with nothing found the plain rectangle crop stays. PDF pages skip detection. The camera hint is now "Fill the frame with the page, straight on."
  - Second pass for small or unsure text: after the first recognize() on the flattened image, every line with confidence under 0.6 (SECOND_PASS_CONFIDENCE) or shorter than 1.2% of the image height (SMALL_LINE_HEIGHT) is cropped from the full-resolution image with padding (0.6 line heights sideways, 0.35 up and down), enlarged 2x with Lanczos (SECOND_PASS_SCALE), and read again, all crops at once on several threads (recognizeRegions in Swift). A line's text, words and alternatives are replaced only when the second reading is more confident; the original line box is kept. At most 40 lines a page (SECOND_PASS_MAX_LINES), least confident first. The added time is logged per page ("[ocr] second pass: n of m lines, k replaced, X ms (native Y ms)").
  - Honest nudge: when more than 10% of a page's words (NUDGE_UNSURE_SHARE) are on lines under the 0.6 threshold, the Result screen shows one slip above that page's text: "Some words were hard to read. A closer, flatter photo usually fixes it." with Retake and Dismiss. It is shown once per page (remembered in the new pages.nudge_seen column); Retake goes back to where the page came from (camera, photos or files; build 1 pages go to the camera) and the new reading replaces the page in place (its edits and the note reset). A retake counts against the free daily scans like any reading.
  - Safe fixes on recognized text (src/text.ts fixToken/fixLine), applied to every recognized line, raw or cleaned up, never to the person's own edits: a lone "I" or "l" before a unit in capitals (CUP, TABLESPOON, TEASPOON, TBSP, TSP, POUND, LB, OUNCE, OZ, PINT, QUART, GALLON, GRAM, KG, ML, LITER, INCH, CLOVE) or before a fraction becomes "1"; "I-INCH" and "I½" start with "1"; fractions Vision returns in pieces ("1⁄2" with a fraction slash, "¹/₂" in small digits) become one fraction character ("½"), or plain "n/d" when there is none. A "%" where a fraction might have been, and a plain "3/4", are left alone; nothing is guessed.
  - Schema version 2 (migrate() in src/db.ts, guarded by PRAGMA user_version and a column check): pages.origin TEXT NOT NULL DEFAULT '' and pages.nudge_seen INTEGER NOT NULL DEFAULT 0. Nothing dropped or renamed; build 1 data keeps working.
  - Pure logic in src/accuracy.ts (thresholds, second-pass pick and merge, the nudge share, page outline order, area, convexity, turning) with unit checks.
